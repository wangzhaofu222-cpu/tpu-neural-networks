# Нейронные сети — лабораторные работы 0–9

Учебный экспериментальный проект Томского политехнического университета.
Автор: Ван Чжаофу. В репозитории представлены реализации, конфигурации,
журналы запусков, статистический анализ и десять официальных отчётов на русском языке.
Все работы используют единый Experiment Harness.

**Состояние на 11 ноября 2026 года:** эксперименты и отчёты Lab 0–9 подготовлены;
результаты доступны для просмотра в локальном MLflow. Отрицательные результаты
и невыполненные численные критерии сохранены и обсуждаются в отчётах.
Завершение экспериментов не означает подтверждения каждой исходной гипотезы.

## Просмотр результатов в MLflow

На подготовленном компьютере запустите **[Open_MLflow.cmd](Open_MLflow.cmd)**.
Интерфейс откроется по адресу <http://127.0.0.1:5000/#/experiments>.
Это локальный сервис: ссылка работает на компьютере с запущенным MLflow,
а не является публичной страницей GitHub.

В MLflow созданы десять experiments — по одному для каждого Lab:

- **973 записи запусков:** обучение, оценка, диагностика и бюджетные проверки;
  число записей не равно числу обученных моделей.
- **10 сводных записей** `00 - Lab N results, figures and report`:
  анализ, графики и официальный отчёт во вкладке **Artifacts**.
- В отдельных запусках доступны параметры, метрики `result.*`,
  кривые `step.*` / `epoch.*`, оригинальные журналы и сведения об источнике.

Результаты импортированы из ранее выполненных экспериментов. Исходные RUN_ID,
версии Git и статусы сохранены; импорт не выдаётся за повторное обучение или
за использование MLflow в момент первоначального запуска. Для отображения
выбирается до 1000 реальных точек каждой кривой с сохранением начала и конца;
полные журналы доступны в Artifacts. Для новых запусков предусмотрен
[scripts/train_with_mlflow.py](scripts/train_with_mlflow.py), который вызывает
существующий тренировочный код и синхронизирует записи после его завершения.

После клонирования можно создать отдельное окружение и восстановить MLflow
из текстовых записей, включённых в репозиторий:

```powershell
python -m venv .mlflow-env
& .\.mlflow-env\Scripts\python.exe -m pip install -r requirements-mlflow.lock.txt
& .\.mlflow-env\Scripts\python.exe -X utf8 scripts/mlflow_sync.py
& .\.mlflow-env\Scripts\python.exe -X utf8 scripts/mlflow_ui.py
```

Повторная синхронизация: **[Sync_MLflow.cmd](Sync_MLflow.cmd)**.
Подробности: [руководство по MLflow](docs/MLFLOW_GUIDE.md).

## Воспроизводимость и данные

Для обучения используется отдельное окружение `.conda-env`.
Версии зависимостей зафиксированы в [requirements.lock.txt](requirements.lock.txt),
[requirements-lab9.lock.txt](requirements-lab9.lock.txt) и файлах
[docs/environment/](docs/environment/). Окружение MLflow изолировано от PyTorch.

Данные готовятся по протоколу соответствующей работы; источники перечислены в
[docs/data_sources.md](docs/data_sources.md). В Lab 5 приняты public masks Cora
из PyG; в Lab 9 используется разбиение по актёрам с seed 1729 и зафиксированный
визуальный кодировщик из Lab 2. Подробности находятся в конфигурациях и
[протоколе дополнительной проверки](experiments/revision_20261106/protocol.md).
Обучающая, валидационная, калибровочная и тестовая роли разделены;
статистики нормализации оцениваются по обучающей выборке там, где это требуется.

Чтобы воспроизвести конкретный результат, найдите его RUN_ID в отчёте и откройте
соответствующую папку `runs/`. Файл `config.resolved.yaml` содержит фактические
условия запуска; `manifest.json` — seed, версию кода, идентификаторы данных и среду.
Для исторического запуска следует использовать указанную версию кода и его
зависимости. Одного базового YAML недостаточно для восстановления всех условий:
отдельные эксперименты используют явные переопределения параметров.

Точка входа обучения — [src/train.py](src/train.py), общий цикл —
[src/engine/runner.py](src/engine/runner.py). При восстановлении обучения сохраняют
исходный полный бюджет и загружают checkpoint со состояниями оптимизатора,
планировщика и генераторов случайных чисел. Настройки по умолчанию для разработки
и бюджетные проверки не считаются завершённым формальным экспериментом.

В Git включены код, конфигурации, текстовые журналы, анализ, отчёты и их рисунки.
Исходные датасеты, полные веса моделей, окружения Python, кеши, локальная база
MLflow и ZIP-пакеты в Git не включены. Checkpoint-файлы хранятся локально;
их пути и контрольные суммы доступны в индексах и MLflow. Для повторного обучения
нужны исходные данные, для восстановления обучения — также checkpoint.
